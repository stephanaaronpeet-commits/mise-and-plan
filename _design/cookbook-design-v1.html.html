VISUAL SPEC · NOT A LIVE APP

Five screens.
Two viewports.
One iron rule.

Every screen below is rendered at both mobile 390 px and desktop 1024 px at literal pixel size, no scaling. Iron-red appears only on protein-related elements — never on buttons, links, or other accents. Stamps, hairline rules, graph-paper grids and tabular numerals are the recurring grammar. Commentary blocks under each section state interaction rules in mono — these are the hand-off notes for the developer.

§01 Interaction notes

  • BROWSE RAIL is sticky on scroll, mobile scrolls horizontally with snap. Active tile inverts to paper-fill.
  • SEARCH matches title + ingredient names + tags. Live-filters cards within 60ms of input.
  • FILTER CHIPS are additive (AND), each shows live count. × dismisses single chip.
  • SORT default: Most cooked. Other: Recently added / Highest protein / Quickest / A-Z.
  • CARDS stagger-reveal on load (30ms steps). Border hovers to paper-200 in 100ms. No shadows, no scale.
  • STAMPS ranked: NEW > FAV > ×N COOKED. Only one stamp per card, top-right.
  • EMPTY only after filter, never on initial load. "Wis filters" clears all chips + search.
  • + ADD RECIPE opens form (§04). Mobile: full-page route. Desktop: modal.

§02 Interaction notes

  • SERVINGS SCALER live-updates ingredient qty (tabular-num, no fade) and macros. ×1.00 shows current scale factor.
  • CHECKBOXES on ingredient rows are local-only state, reset on close. They are for cooking-now usage. Not persisted.
  • SUBSTITUTION TOGGLES mutate the displayed ingredient list AND macros in-place. Delta colors: red = increase, green = decrease (regardless of "good/bad"), paper = neutral.
  • TIMER TAG on a step is informational here. In cook mode (§03) it becomes interactive.
  • STICKY BAR stays fixed at the bottom of viewport on mobile. Desktop it ends the scroll naturally.
  • STAR toggles favorite. ⋯ opens menu: Edit · Duplicate · Delete · Export JSON · Share.
  • DESKTOP LAYOUT goes 2-col below the macro row: ingredients + subs left, method + notes + serves-with right.
  • HERO PHOTO no zoom, no parallax. Static. 16:9 mobile / desktop, 1:1 in cards.
§ 03 · Cook Mode
Inverted · counter-readable at 60 cm

Hands free.
60 cm away.

Cook mode flips to the paper-on-iron-reversed scheme: cream background, iron type, ruled with graph-paper at high contrast. One step at a time, huge numerals, optional timer block. Three states shown: (A) no-timer step, (B) timer ready, (C) timer counting. Swipe left/right to navigate; tap timer to start. Wake-lock keeps the screen on.

§03 Interaction notes

  • COLOR INVERSION is intentional and only here. Lighter background = readable from 60 cm in a counter-lit kitchen.
  • SWIPE hard left/right with snap. No fade. arrow keys on desktop, space = next.
  • TIMER tap to start → counts down → vibrates on zero (mobile) + plays single beep. Digit turns iron-red while running.
  • PROGRESS BAR 5 segments, current = iron-red, prior = iron-black, future = paper-200 outlined.
  • WAKE LOCK via Screen Wake Lock API on enter. Released on exit (×). Fallback: warn on first open if API missing.
  • EXIT via × prompts only if a timer is running. Otherwise dismiss instantly.
  • DESKTOP shows the same UI scaled up to 880px wide, centered. Same logic.
  • NO BOUNCE no spring, no elastic, no confetti at end. End-state = step 5 done → "Mark as cooked" outline button. That's it.

§04 Interaction notes

  • PASTE FROM CLAUDE accepts: pasted JSON object · pasted raw recipe text · dropped .json file. Detects format, populates fields. Diff-summary toast on success.
  • VALIDATION live: required fields (title, servings, ingredients ≥ 1, steps ≥ 1, macros). Errors marked iron-red on the input border, no toasts.
  • ROW BUILDERS are drag-reorderable (≡), unit dropdown opens picker, category auto-suggests based on item match. Empty row at bottom is the "add" affordance.
  • TOTAL TIME auto-sums prep + cook on every change, read-only.
  • MOBILE LAYOUT stacked single-column. Desktop = 2-col with left wide (basics, ing, subs), right narrow (time, macros, steps, notes).
  • SAVE & EXPORT JSON writes recipe and downloads a .json snapshot using the exact schema from the brief.
  • SAVE DRAFT persists incomplete record with status draft — appears in cookbook with DRAFT stamp.
  • EDIT MODE identical form, pre-filled, with a header "EDITING: [title]" replacing "NEW · RECIPE".

§05 Reuse notes

  • PRIMITIVES FIRST — every screen above is assembled from these. If a screen needs something not in this kit, add it here, don't one-off it.
  • NO ROUNDED CORNERS on anything ever. 1px max. Boxes, chips, buttons, inputs — all square.
  • NO SHADOWS. Depth comes from borders and color steps only.
  • NO GRADIENTS except graph-paper grid. Solid fills only.
  • IRON-RED LOCK — appears only on protein-data, the timer-active glyph, the structural top-border of the sticky bar, and the active progress-bar segment. Nowhere else.
  • ANIMATIONS are all linear 100–280ms. No spring, no bounce. Mechanical.
  • TYPE SCALES — display ≥ 18px (chip labels at 18, h4 in cards at 22). Mono never below 9px. Body never below 12px.
